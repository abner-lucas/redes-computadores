Conectar-se a um Servidor Web

Observe na prática como os pacotes ICMP (ping) e HTTP são enviados entre duas redes IP diferentes (192.168.1.0/24 e 172.33.100.0/24) atravessando switches e um roteador Cisco 2811 até carregar uma página HTML no navegador do cliente.

  • Host Origem: PC0 (192.168.1.100/24)
  • Roteador: Cisco 2811 (2 sub-redes)
  • Destino: Servidor Web (172.33.100.50/24)
  • Página Web: Traduzida para o Português

Etapas do Laboratório

Realize os testes de conectividade e observe a diferença entre o protocolo de diagnóstico (ICMP Ping) e o protocolo de aplicação (HTTP).

0 de 3 etapas concluídas (0%)
  1. Etapa 01
    1. Clique no computador PC0 → selecione a guia Desktop → clique em Command Prompt (Prompt de Comando).
    2. Digite o comando ping 172.33.100.50 e pressione Enter.
    3. Observe a resposta: o primeiro pacote pode falhar (25% de perda) enquanto o protocolo ARP descobre o endereço MAC do gateway e do servidor, e os 3 pacotes seguintes retornam com TTL=127 (o TTL inicial 128 perdeu 1 unidade ao atravessar o Router0).
  2. Etapa 02
    1. Feche apenas a janela do Command Prompt para voltar à guia Desktop do PC0.
    2. Clique no ícone Web Browser (Navegador Web).
    3. No campo URL, digite o endereço IP do servidor: 172.33.100.50 e clique em Go.
    4. A página HTML hospedada no servidor será carregada na tela: "Bem-vindo ao Servidor Web de Redes - IFPA".
  3. Etapa 03
    1. No canto inferior direito do Packet Tracer, alterne de Realtime para Simulation (Simulação).
    2. No navegador do PC0, clique novamente em Go para requisitar 172.33.100.50.
    3. Clique no botão Forward (▶|) para avançar salto a salto e clique sobre o envelope colorido para inspecionar as camadas do Modelo OSI (Porta TCP 80 na Camada 4, IPs na Camada 3 e quadros Ethernet na Camada 2)!
